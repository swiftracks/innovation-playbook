# North Star and Supporting Metrics

## Purpose

Define a measurement system that improves both learning speed and decision quality.

## Who this is for

- Teams instrumenting their cycle performance.
- Program operators running cross-team reviews.

## North Star

**Median learning cycle time** from **assumption selection -> validated learnings**.

This is the north star because it directly measures how quickly teams turn a selected uncertainty into reviewable, validated learning.

It is not enough on its own, though. A shorter cycle is only valuable if the learning is still strong enough to support good decisions.

Operationally, teams should mark the start of the cycle when a specific assumption is selected for focused testing, and the endpoint when a learning is strong enough to be treated as validated and usable in synthesis. Programs should measure this consistently across teams or the metric becomes noisy and hard to compare.

## Supporting metrics

- Learning quality rubric score.
- Percentage of cycles completed without rework.
- Time from project start to first validated learning.
- Stage-gate pass rate.
- Mentor feedback adoption rate.
- Cohort-level completion rate.

## What these metrics tell you

- **Learning quality rubric score** tells you whether faster cycles are still producing usable outputs.
- **Cycles completed without rework** tells you whether quality is strong enough early in the process.
- **Time from project start to first validated learning** tells you how quickly teams move from setup to real evidence.
- **Stage-gate pass rate** shows where teams are most often getting stuck.
- **Mentor feedback adoption rate** shows whether review input is actually improving the work.
- **Cohort-level completion rate** helps program leaders compare execution health across teams.

## Usage guidance

- Review weekly at team level.
- Review bi-weekly at program level.
- Use trends, not single data points, to trigger process changes.

## How to interpret the metrics responsibly

- If cycle time drops but rubric scores fall, the team may be moving faster at lower quality.
- If rubric scores are high but cycle time keeps stretching, the team may be over-processing or delaying decisions.
- If mentor feedback is high but adoption is low, reviews may not be practical enough.
- If stage-gate pass rate is weak at the same point repeatedly, the issue is likely systemic, not individual.

The goal is not to optimize one number in isolation. The goal is to improve the whole learning system.

## Definition of done

- Metric definitions are consistent across teams.
- Review cadence is established and followed.
- Interventions are selected based on trends, not one-off anomalies.
