# Decide What to Build

> **Purpose**: Validate ideas before building to reduce waste and increase success
> **Outcome**: Make data-driven decisions about what to build based on validated assumptions
> **Audience**: PM / Dev / Both
> **Time**: 2-4 weeks (depending on complexity)
> **Prerequisites**: [Start Here](start-here/index.md)

## Learning Outcomes

By the end of this section, you will be able to:
1. Articulate clear problem statements and value propositions
2. Identify critical assumptions that must be true for success
3. Formulate testable hypotheses with measurable outcomes
4. Design and run experiments to validate assumptions
5. Synthesize learnings into go/no-go decisions

## Jobs-to-Be-Done

- **When**: I have an idea for a product or feature
- **I want**: To validate it before building
- **So that**: I can avoid wasting time on products that won't succeed

## Inputs

- Initial idea or problem hypothesis
- Access to potential users or customers
- Understanding of Jobs-to-Be-Done framework
- Time for experimentation (2-4 weeks recommended)

## Activities

This section follows a systematic validation process:

1. **[01 — Idea / Problem](01-idea-problem.md)**: Articulate the problem and value proposition
2. **[02 — Identify Critical Assumptions](02-identify-critical-assumptions.md)**: Find what must be true for success
3. **[03 — Form Testable Hypotheses](03-form-testable-hypotheses.md)**: Create testable statements
4. **[04 — Design & Run Experiments](04-design-run-experiments.md)**: Test your hypotheses
5. **[05 — Extract Key Learnings](05-extract-key-learnings.md)**: Analyze results and insights
6. **[06 — Synthesize Insights → Decision](06-synthesize-insights-decision.md)**: Make a go/no-go decision

> 💡 **Tip**: These chapters must be done sequentially. Each builds on the previous one.

## Worked Example

**Situation**: Validating a product idea for improving team retrospectives

**Process**:
1. **Problem**: Teams struggle to get actionable insights from retrospectives
2. **Critical Assumption**: Teams will use an AI-powered retrospective tool
3. **Hypothesis**: If we provide AI-generated insights, then teams will complete retrospectives faster
4. **Experiment**: Landed page with mockups, measure signup interest
5. **Learning**: 40% of teams showed interest, but needed more specific value
6. **Decision**: Proceed to build MVP with refined value proposition
