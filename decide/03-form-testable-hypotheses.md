# 03 — Form Testable Hypotheses

> **Purpose**: Convert critical assumptions into testable hypotheses
> **Outcome**: Have clear, measurable hypotheses ready for experimentation
> **Audience**: PM / Dev / Both
> **Time**: 2-3 hours
> **Prerequisites**: [02 — Identify Critical Assumptions](02-identify-critical-assumptions.md)

## Learning Outcomes

By the end of this chapter, you will be able to:
1. Write clear, testable hypotheses
2. Use the hypothesis format: "We believe... If... Then... We'll know..."
3. Define measurable success criteria
4. Prioritize hypotheses for testing
5. Prepare hypotheses for experiment design

## Jobs-to-Be-Done

- **When**: I have a list of critical assumptions
- **I want**: To convert them into testable hypotheses
- **So that**: I can design experiments to validate or invalidate them

## Inputs

- Critical assumptions list from [02 — Identify Critical Assumptions](02-identify-critical-assumptions.md)
- Problem statement and value proposition
- Understanding of what you want to learn

## Activities

### 1. Use the Hypothesis Format

Convert assumptions to hypotheses using this format:

```
We believe [assumption].
If [condition],
Then [outcome].
We'll know this is true when [metric].
```

**Example**:
```
We believe teams will use an AI-powered retrospective tool.
If we create a landing page with mockups,
Then at least 30% of visitors will sign up for early access.
We'll know this is true when we see 30%+ conversion rate.
```

> 💡 **Tip**: Make hypotheses specific and measurable. Avoid vague outcomes.

### 2. Define Success Criteria

For each hypothesis, define:
- **Metric**: What you'll measure
- **Threshold**: What success looks like
- **Timeline**: When you'll measure
- **Sample Size**: How many users/data points needed

**Example**:
```
Metric: Signup conversion rate
Threshold: 30% or higher
Timeline: After 100 visitors
Sample Size: 100 visitors minimum
```

### 3. Prioritize Hypotheses

Prioritize by:
- **Risk**: How risky is the assumption?
- **Impact**: How much does it matter?
- **Testability**: How easy is it to test?
- **Dependencies**: Does it depend on other hypotheses?

> 🎯 **Goal**: Test the riskiest, highest-impact hypotheses first.

### 4. Create Hypothesis Canvas

Use this structure:

```
Hypothesis: [Full hypothesis statement]
Assumption: [Underlying assumption]
Category: [User/Technical/Business/Value]
Priority: [High/Medium/Low]
Success Criteria:
  - Metric: [What to measure]
  - Threshold: [Success threshold]
  - Timeline: [When to measure]
  - Sample Size: [How many needed]
Test Method: [How you'll test it]
```

### 5. Document Hypothesis Set

Create a prioritized list:

**Top Priority** (test first):
- Hypothesis 1: [Critical assumption]
- Hypothesis 2: [Next critical assumption]

**Medium Priority** (test if time/resources allow):
- Hypothesis 3: [Important assumption]
- Hypothesis 4: [Important assumption]

**Low Priority** (track but don't prioritize):
- Hypothesis 5: [Less critical assumption]

## Apply It Now

**Task**: Create your testable hypotheses

1. Convert your top 5 critical assumptions into hypotheses using the format
2. Define success criteria for each hypothesis (metric, threshold, timeline, sample size)
3. Prioritize hypotheses by risk, impact, and testability
4. Create hypothesis canvases for your top 3-5 hypotheses
5. Document your hypothesis set with priorities

**Artifact**: A hypothesis document with:
- Hypothesis statements in the correct format
- Success criteria for each
- Priority ranking
- Hypothesis canvases

## Artifacts

You'll create:
- Testable hypotheses document
- Hypothesis canvases
- Success criteria definitions
- Prioritized hypothesis list

## Worked Example

**Situation**: Retrospective tool product idea

**Hypothesis 1** (Top Priority):
```
Hypothesis: We believe teams will use an AI-powered retrospective tool. If we create a landing page with mockups, then at least 30% of visitors will sign up for early access. We'll know this is true when we see 30%+ conversion rate after 100 visitors.

Assumption: Teams will use an AI-powered retrospective tool
Category: User
Priority: High
Success Criteria:
  - Metric: Signup conversion rate
  - Threshold: 30% or higher
  - Timeline: After 100 visitors
  - Sample Size: 100 visitors minimum
Test Method: Landing page with mockups, measure signup rate
```

**Hypothesis 2** (Top Priority):
```
Hypothesis: We believe we can build AI that generates useful insights. If we build an MVP with basic AI, then at least 70% of users will rate insights as useful. We'll know this is true when we see 70%+ usefulness rating in user testing.

Assumption: We can build AI that generates useful insights
Category: Technical
Priority: High
Success Criteria:
  - Metric: Usefulness rating (% rating insights as useful)
  - Threshold: 70% or higher
  - Timeline: After testing with 10 teams
  - Sample Size: 10 teams minimum
Test Method: Build MVP, test with real retrospectives
```

**Hypothesis 3** (Medium Priority):
```
Hypothesis: We believe users will pay $10/month for this tool. If we create a pricing page with signup, then at least 20% of visitors will sign up. We'll know this is true when we see 20%+ conversion rate after 100 visitors.

Assumption: Users will pay $10/month for this tool
Category: Business
Priority: Medium
Success Criteria:
  - Metric: Signup conversion rate at $10/month
  - Threshold: 20% or higher
  - Timeline: After 100 visitors
  - Sample Size: 100 visitors minimum
Test Method: Pricing page with signup, measure conversion
```
