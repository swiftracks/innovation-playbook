# 09 — Private Beta

**Purpose**: Launch MVP to select users for testing and feedback

**Outcome**: Have real users using your MVP and providing feedback

**Audience**: PM / Dev / Both

**Time**: 2-4 weeks

**Prerequisites**: [09 — Deploy](build/09-deploy.md)

## Learning Outcomes

By the end of this chapter, you will be able to:
1. Plan a private beta launch
2. Recruit and onboard beta users
3. Launch MVP to real users
4. Gather initial feedback
5. Monitor usage and issues

## Jobs-to-Be-Done

- **When**: I have a working MVP ready for testing
- **I want**: To launch it to select users
- **So that**: I can learn from real usage and gather feedback

## Inputs

- Working MVP from [Build the MVP](build/index.md)
- Quality and observability setup
- Access to potential beta users
- Understanding of what to learn

## Activities

### 1. Plan Private Beta

**Define Beta Goals**:
- What do you want to learn?
- What metrics will you track?
- How long will beta last?
- What success looks like?

**Example Goals**:
- Validate core value proposition
- Test user journey completion
- Gather feedback on UX
- Identify bugs and issues

### 2. Recruit Beta Users

**Identify Target Users**:
- Who are your target users?
- How many do you need?
- Where can you find them?

**Recruitment Methods**:
- Personal network
- Social media
- Communities
- Existing users (if any)

**Beta Size**:
- **Small**: 5-10 users (early feedback)
- **Medium**: 10-20 users (more data)
- **Large**: 20-50 users (statistical significance)

> 💡 **Tip**: Start small. 10-20 users is enough for initial feedback.

### 3. Set Up Onboarding

**Onboarding Process**:
- Welcome email
- Getting started guide
- Access instructions
- Support channels

**Example Onboarding**:
1. Welcome email with access link
2. Getting started guide (5 minutes)
3. First use walkthrough
4. Support Slack channel or email

### 4. Launch MVP

**Launch Steps**:
1. Final testing and QA
2. Deploy to production
3. Send access to beta users
4. Monitor for issues
5. Gather initial feedback

**Launch Checklist**:
- [ ] MVP is tested and working
- [ ] Quality and observability are set up
- [ ] Onboarding materials are ready
- [ ] Support channels are ready
- [ ] Monitoring is active

### 5. Monitor and Gather Feedback

**Monitor Usage**:
- Track user activity
- Monitor errors and issues
- Watch analytics
- Check health monitoring

**Gather Feedback**:
- User interviews
- Surveys
- Support requests
- Analytics insights

**Feedback Channels**:
- Weekly check-ins
- Feedback forms
- Support channels
- User interviews

## Worked Example

**Situation**: Launching retrospective tool MVP

**Beta Plan**:
- Goals: Validate value proposition, test user journey, gather feedback
- Metrics: User signup, journey completion, time to value
- Duration: 2 weeks
- Users: 15 engineering teams

**Recruitment**:
- Personal network: 5 teams
- Social media: 5 teams
- Communities: 5 teams

**Onboarding**:
1. Welcome email with access link
2. Getting started guide (5 minutes)
3. First use walkthrough
4. Support Slack channel

**Launch**:
- Final testing: Complete
- Deploy: Production
- Send access: All 15 teams
- Monitor: Active

**Results** (Week 1):
- 12 out of 15 teams signed up
- 8 out of 12 completed journey
- Average time to value: 5 minutes
- Feedback: "Easy to use", "Insights are helpful"
