# Roadmap and Handoff

This section separates current operational guidance from future-state and adjacent workflows.

## Current focus

The primary docs path focuses on learning-cycle execution in SwiftCNS.

That is intentional. The current GitBook is designed to help teams get strong at one thing first: running the learning system well.

## Supporting handoff resources

When teams complete decision-ready validation, they can use:
- [Build the MVP](build/index.md)
- Existing build templates in the `build/` section

Think of those resources as adjacent handoff material, not part of the primary SwiftCNS learning path in this version of the GitBook.

If you are reading this page in the middle of a cycle, that is usually a signal to pause and ask whether the current learning path is actually complete yet. Most teams benefit more from finishing the loop well than from jumping forward too early.

## Why this distinction matters

One of the easiest ways to weaken a learning system is to mix validation guidance, build guidance, and future-state roadmap material into one blurred journey.

This page keeps those layers separate:

| Layer | What it means now |
| --- | --- |
| Current primary path | How to run learning cycles in SwiftCNS today |
| Handoff material | What teams may use after decision-ready validation |
| Roadmap | Areas that may become more central as product capabilities expand |

## Roadmap note

Advanced analytics and command-center capabilities should be treated as planned unless explicitly documented as live in product.

The rule is simple: if a capability is not part of the active documented workflow, do not assume it is core to the current operating model yet.

If a reader reaches this page, the right next question is usually not “What else can I read?” but “What part of the current path do I still need to execute well?” That is why the handoff and roadmap stay secondary here.
